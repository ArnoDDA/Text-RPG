# Secret Fire 统一行动裁定

> 状态：第一版设计方案
> 核心：事实优先、方法驱动、无骰裁定。
> 目标：既守住世界能力边界，又允许准备、环境、关系、动机和创造性方法改变结果。

## 一、裁定的对象不是“角色能不能赢”

系统只裁定玩家这一次声明的具体目标和方法。

同一个场景中，下列行动不是同一项裁定：

- 徒手杀死古龙；
- 激怒古龙，让它离开洞口；
- 趁古龙转身时逃进狭窄石缝；
- 用古龙在意的秘密换取通行；
- 引爆已经布置好的洞窟，使岩层暂时困住古龙。

角色与古龙的“综合强弱”不能直接决定这五件事。每种方法面对的阻力、需要的能力和可能付出的代价都不同。

## 二、什么时候不需要裁定

每次人物出现、说话或进行日常行为时都计算，会造成不必要的负担。只有同时满足下列条件时才进入完整裁定：

1. 行动结果存在真实分歧；
2. 场景中存在阻力、风险或资源限制；
3. 不同结果会对当前故事产生实际影响。

因此，行动先分为三类：

| 类型 | 处理方式 |
| --- | --- |
| 确定可行 | 直接发生，不计算。例如健康成年人走过平坦房间。 |
| 确定不可行 | 明确说明现实边界，不制造虚假尝试。例如普通人徒手举起城门。 |
| 存在争议 | 进入统一裁定。例如在守卫转身前翻过高墙。 |

“不可行”只否定当前方法，不否定玩家的最终目标。系统应允许玩家更换方法、制造条件或改变目标。

## 三、一次裁定需要的行动框架

系统从玩家输入和当前场景中只提取七项内容：

| 内容 | 含义 |
| --- | --- |
| 目标 | 玩家真正想改变什么。 |
| 方法 | 玩家具体如何行动。 |
| 对象 | 行动针对的人、物、地点或局势。 |
| 主要属性 | 当前方法最依赖的一项属性，只选一项。 |
| 专业或能力 | 角色是否真正学过、拥有或能够使用这种方法。 |
| 阻力 | 对手的相关能力，或障碍本身的难度。 |
| 风险 | 失败或勉强成功时，场景中已经存在的合理代价。 |

如果玩家的描述缺少细节，系统采用最直接、最少替玩家做决定的解释。只有不同解释会导致明显不同的重大后果时，才询问一句澄清问题。

一段输入包含多个连续步骤时，不一次裁定整条行动链。例如“我潜入王宫、偷走王冠再逃出城”应在遇到第一个有意义的阻力时停下，而不是用一次成功包办全部过程。

## 四、先检查事实门槛

属性比较之前，先检查以下事实：

- **存在性**：角色、物品、道路或信息是否真实存在；
- **接触条件**：距离、位置、视线、语言和时间是否允许行动；
- **能力来源**：角色是否会这种技术、法术或特殊能力；
- **资源条件**：是否拥有工具、材料、法术资源、金钱或帮助者；
- **规模与范围**：行动能影响的对象数量、区域和持续时间是否足够；
- **硬性免疫或权限**：目标是否免疫、受法则保护，或需要特定钥匙与身份；
- **知识边界**：角色是否知道足以采用这种方法的信息。

这些门槛不会转化为大量加减值。缺少必要条件时，方法受阻；拥有决定性条件时，方法可能直接成立或面对完全不同的阻力。

例如，高智识不能让从未学过医术的人完成精密手术，高魅力不能让对方泄露其根本不知道的秘密，高灵能也不能自动使用从未掌握的法术。

## 五、确定主要属性与阻力

### 1. 一次行动只使用一项主要属性

其他属性不相加，也不取平均。玩家采用的方法决定主要属性：

- 撞开门依赖体魄；寻找机关依赖感知；理解机关依赖智识；
- 用速度躲开攻击依赖身手；提前发现伏击依赖感知；
- 以气势震慑依赖魅力；以证据迫使对方让步依赖事实与智识；
- 承载大型法术依赖灵能；维持濒临失控的法术可能依赖心性。

方法改变，主要属性和阻力也会改变。这是自由度的主要来源，而不是给同一次行动叠加所有高属性。

### 2. 阻力分为人物阻力和环境阻力

- **人物阻力**：使用对方针对当前方法最相关的属性、专业、状态与动机。
- **环境阻力**：使用完成这件事通常需要达到的能力门槛。

环境阻力沿用十点档位：

| 阻力 | 代表难度 |
| --- | --- |
| `10` | 普通成年人通常能处理的日常障碍。 |
| `20` | 需要训练、合适工具或较好天赋。 |
| `30` | 专业人士中的熟练者才能稳定完成。 |
| `40` | 凡人精英或大师级挑战。 |
| `50` | 通常超出正常凡人的稳定能力。 |
| `60–69` | 传奇危险或大型超凡障碍。 |
| `70–79` | 高阶超自然阻力。 |
| `80–89` | 神话级阻力。 |
| `90–99` | 接近世界常规边界。 |
| `100+` | 神明、权柄或法则层面的限制。 |

同一对象面对不同方法时阻力可以不同。一扇精密符文门可能需要 `40` 的身手与开锁专业、`30` 的智识与符文知识、`60` 的体魄才能破坏，却只需要一把真正的钥匙就能直接打开。

## 六、基础差距

比较主要属性与阻力，得到基础能力关系：

| 差距 | 基础判断 |
| --- | --- |
| 行动者高 `20+` | 压倒性优势。基础结果为完整成功，并可能成为优势成功。 |
| 行动者高 `10–19` | 明确优势。基础结果为完整成功。 |
| 相差不足 `10` | 同一竞争层级。基础结果为有限成功；目标不可分割时暂时维持现状。 |
| 行动者低 `10–19` | 明确劣势。基础结果为受阻，需要强力条件才能取得有限或完整成功。 |
| 行动者低 `20+` | 当前方法基本无法跨越。必须改变方法、目标或现实条件。 |

二十点鸿沟不能靠堆砌许多轻微理由跨越。“我很勇敢、很愤怒、冲得很快、喊得很响”不能让普通人正面压倒古龙。只有真正改变问题的事实才有作用，例如古龙已经濒死、存在专门克制它的武器，或玩家根本不再尝试正面对抗。

## 七、情境优势不做无限加减法

在相近层级中，系统只保留双方各自最重要的至多两个情境优势。相同来源的描述合并计算，避免玩家或 AI 通过堆砌形容词获得额外收益。

可以构成情境优势的事实包括：

- 与方法直接相关的专业训练；
- 合适而有效的工具或装备；
- 有实际作用的准备、情报与埋伏；
- 对手的伤势、疲劳、分心或错误判断；
- 地形、距离、光线、天气与掩护；
- 关系、身份、证据、筹码和目标动机；
- 可靠协助，但多人属性不相加，只形成协作优势；
- 对当前方法有效的特殊能力。

处理方式：

- 可移动的结果顺序为“受阻 → 有限成功 → 完整成功 → 优势成功”；“不可行”属于硬边界，不在普通移动序列中；
- 双方优势相互抵消；
- 净一项优势，使结果向有利方向移动一级；
- 净两项优势，最多移动两级；
- 普通情境优势不能直接穿越二十点鸿沟；
- 能够改变门槛、方法或阻力对象的事实属于“决定性事实”，应重新建立行动框架，而不是作为第三、第四个加成。

这里的“一级”是结果等级，不需要真的修改或保存人物属性。

## 八、五种结果

| 结果 | 含义 |
| --- | --- |
| 不可行 | 当前方法触碰硬边界，行动不能产生预期效果。 |
| 受阻 | 行动实施了，但目标没有实现，并触发现实中已经存在的风险。 |
| 有限成功 | 达成部分目标、暂时达成目标，或成功但付出明确代价。 |
| 完整成功 | 以声明的方法实现目标，没有额外惩罚。 |
| 优势成功 | 在压倒性能力与充分条件下，除目标外还获得一个自然附带收益。 |

结果必须来自行动框架中已经存在的因素，不能为了戏剧性临时制造代价。例如失败可能导致时间流逝、位置暴露、工具损坏、关系恶化、伤势或机会消失，但前提是该风险在当前行动中真实存在。

完全势均力敌且没有任何一方拥有有效优势时：

- 如果目标可以分割，产生有限进展或有代价的成功；
- 如果目标不可分割，维持现状，防守方或既有状态占优；
- 系统不得暗中随机选择胜负。

## 九、重复尝试与信息边界

- 同一人物在条件完全不变时，用同一方法重复行动，应得到相同结果；不存在“再试一次也许随机成功”。
- 再次尝试必须改变方法、获得新工具、投入更多时间、接受更大风险或改变现场条件。
- 系统可以使用角色尚不知道的真实事实进行裁定，但叙述只能呈现角色能够观察到的结果，不能泄露秘密原因。
- NPC 使用同一套规则，不能因为剧情需要临时突破属性、资源或知识边界。

## 十、三个边界示例

### 1. 普通矮人徒手杀死古龙

- 目标：杀死古龙；方法：正面徒手攻击。
- 事实门槛：体型、攻击手段和伤害规模均不够。
- 能力差距：超过二十点，并存在规模鸿沟。
- 结果：不可行。勇气、愤怒和偶然位置不会使攻击突然致命。
- 可改变的方向：逃跑、交涉、寻找克制武器、利用洞窟结构、攻击已经暴露的特殊弱点。

### 2. 玩家从疲惫的大法师手中逃走

- 目标：离开现场，不是击败法师。
- 方法：利用出口、遮挡和法师的疲惫迅速脱离。
- 主要比较：玩家的身手或路线判断，对抗法师当前追击能力与真实动机。
- 情境事实：法师灵能强大不等于愿意或能够立刻追击；疲劳、分心、受伤、出口距离和是否必须保护别的东西都可能成为决定性事实。
- 结果：即使玩家绝对无法战胜法师，也可能完整逃脱、带伤逃脱，或暂时拉开距离。

### 3. 高魅力角色说服忠诚守卫背叛君主

- 目标：让守卫背叛根本誓言；方法：一次谈话。
- 事实门槛：魅力不是精神控制，守卫的动机与底线限定结果上限。
- 结果：通常不可直接完成。高魅力可以让守卫愿意听、暂缓逮捕、透露顾虑或留下再次接触的机会。
- 可改变的方向：提供君主背叛守卫的证据、建立长期信任、交换重要人质或改变守卫所保护的对象。

## 十一、低计算量实现原则

每次真正需要裁定时，系统只处理：

1. 一个明确目标；
2. 一种当前方法；
3. 一项主要属性；
4. 一个阻力值或对手能力；
5. 双方各至多两个关键情境优势；
6. 一个结果和必要的状态变化。

不需要读取所有人物的七项属性，也不需要持续计算全世界。普通背景人物只生成当前场景需要的一项能力范围；人物成为重要角色后，再保存已经在剧情中确认的属性、专业、动机与状态。

## 十二、系统内部裁定记录

为了让结果可检查，系统可以保存一份不直接展示给玩家的精简记录：

```text
目标：越过城墙
方法：借雨夜从排水槽攀爬
主要属性：身手 27
专业：攀爬（熟练）
阻力：湿滑高墙 30
行动者优势：熟悉排水槽
阻力优势：暴雨
基础关系：同层级
最终结果：有限成功
代价：耗时增加，手掌受轻伤
```

这份记录用于保持前后一致，不应把数字和内部判断机械地塞进剧情正文。

## 十三、仍需通过游玩确认的部分

- 情境优势移动一级是否足够明显；
- “有限成功”出现频率是否会过高；
- 环境阻力的十点档位是否容易稳定标定；
- 哪些伤势、资源和关系变化必须由玩家确认后写入；
- 是否需要让玩家在高风险行动前明确获知最严重的可能后果。

第一版应先按本规则进行数十回合真实游玩，再根据具体争议调整，而不是继续增加更多修正项。

## 十四、实际运行流程

统一裁定不应完全交给 AI，也不应要求本地程序理解所有自然语言。实际运行采用三方分工：

| 部分 | 负责内容 | 不允许做的事 |
| --- | --- | --- |
| 本地数据库 | 保存属性、专业、物品、状态、地点、关系、秘密、NPC 动机和已经确定的障碍 | 不自行编造剧情或猜测玩家意图 |
| AI 行动解释器 | 从自由输入中识别目标、方法、对象、主要属性和相关事实 | 不直接决定最终成功等级，不得引用数据库中不存在的能力与物品 |
| 本地裁定器 | 检查事实编号、读取真实数值、比较差距、计算至多两个优势并锁定结果 | 不根据戏剧需要临时修改属性、阻力或事实 |
| AI 叙事者 | 把已经锁定的结果写成自然剧情，并扮演 NPC 的可见反应 | 不推翻裁定，不替玩家追加行动，不泄露角色未知事实 |

### 1. 每个玩家回合的顺序

1. 玩家提交一段自然语言行动。
2. 本地系统读取当前场景，并只检索与这段行动有关的人物、属性、专业、状态、物品、关系和环境事实。
3. AI 将输入整理为结构化“行动框架”，但不能自行填写角色真实数值。
4. 本地程序用数据库中的数值和事实补全框架，拒绝不存在的物品、能力与优势。
5. 本地裁定器按照二十点鸿沟和结果阶梯锁定结果。
6. AI 只能围绕这个结果生成中文剧情和 NPC 反应。
7. 本地程序检查叙述与状态变化是否一致，再把事件、伤势、位置、关系和消耗写入存档。

### 2. 行动框架示例

玩家输入：

```text
我趁大法师已经疲惫，踢翻烛台挡住他的视线，从侧门逃出去。
```

AI 解释器只返回类似内容：

```json
{
  "goal": "脱离房间",
  "method": "制造遮挡后从侧门快速逃离",
  "target": "侧门与大法师的追击",
  "primary_attribute": "身手",
  "expertise_ids": [],
  "actor_fact_ids": ["scene_overturned_candles", "scene_side_door_nearby"],
  "opposition_actor_id": "archmage_varen",
  "opposition_attribute": "感知",
  "opposition_fact_ids": ["varen_exhausted", "varen_protecting_ritual"],
  "declared_risk": "若受阻，会暴露逃跑方向并失去距离"
}
```

随后本地程序读取真实数据，例如：

```text
玩家身手：27
法师感知：42
基础差距：-15，基础结果“受阻”
有效优势：遮挡视线、法师必须保护仪式
净优势：2，结果上移两级
锁定结果：完整成功
```

AI 叙事者收到的不是开放问题，而是明确约束：玩家成功离开房间；法师不能被击败；仪式仍在继续；不能替玩家决定逃出门后的下一步。它只负责把这些事实写成自然场景。

### 3. 程序必须验证的内容

- 主要属性必须是七项属性之一；
- 属性值必须从存档读取，AI 无权提供；
- 专业、物品、关系和状态必须引用已有记录；
- 双方普通优势各不得超过两个；
- 二十点以上的差距不能被普通优势移动；
- 新障碍第一次出现时按十点档位确定阻力并保存，重复面对时不能临时改难度；
- 最终叙述不得与锁定结果相反；
- 资源消耗、伤势、位置和关系变化必须与叙述中真实发生的内容一致。

### 4. 为了控制速度，采用分级运行

- **日常行动**：不运行完整裁定，直接由叙事者处理。
- **普通争议行动**：一次结构化裁定后直接叙述。
- **高风险行动**：涉及死亡、永久伤残、重大财产、核心关系决裂或世界级变化时，将“解释与裁定”和“剧情叙述”分成两个阶段，并保留内部裁定记录。

第一版原型可以先让一次 AI 返回“行动框架 + 受约束叙述”，由本地程序验证并在不一致时拒绝提交。这不会增加正常回合的模型调用。待真实游玩证明高风险场景仍不稳定后，再只对高风险行动启用两阶段调用，而不是让所有回合都变慢。
