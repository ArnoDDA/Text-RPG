# Secret Fire：当前状态、缺口与推进路线

> 整理日期：2026-10-13。本文描述的是可交付项目的当前能力，不把尚未实现
> 的想法写成已完成的功能。

## 一、产品边界已经确定

Secret Fire 是一个由本机 Codex 叙述、由本地 SQLite 保存状态的单人文字
角色扮演游戏。它不是聊天记录包装器，也不是重规则战术 RPG。

- **叙事中心**：第三人称、中文剧情输出、玩家自由输入行动。
- **世界中心**：固定的“迷失之地”百科提供所有存档共同遵守的世界大纲；
  游戏中已经成立的具体地点、人物、组织与事件跟随存档，离开后仍可返回和延续。
- **存档中心**：世界、人物、物品、事实、秘密认知、剧情线、检查点和分支
  均归本地数据库管理。
- **模型边界**：Codex 只处理当前一回合，采用临时线程，不承担长期会话记忆。
- **轻量原则**：没有额外模型服务、向量数据库、后台队列、持续轮询或复杂战斗
  引擎。

## 二、已经完成并可用的功能

| 区域 | 已完成内容 | 说明 |
| --- | --- | --- |
| 本地运行 | `npm run start` 启动 127.0.0.1 服务 | 不需要 API Key；使用当前电脑已登录的 Codex。 |
| 世界与存档 | 多个独立存档、一个固定世界大纲、具体地点与路线持久化、检查点、分支、恢复、删除分支、重新开始 | 地点离开后仍保存并可返回；恢复检查点永远创建新时间线，不覆盖原剧情。 |
| 长期记忆 | 场景、事实、NPC 信念、剧情线、实体状态、近况与世界百科按需检索 | 每 25 回合保留完整恢复锚点，其间写入紧凑状态差量。 |
| 物品 | 本地关键物品账本、状态、数量、用途、装备位与手动确认 | 叙事模型只能提出物品建议，不能直接改写库存。 |
| 交易与资源 | 分支钱包、当前场景报价、购买/出售/报酬/支付、最近交易记录 | 本地原子结算余额与物品；模型只能提出报价，不能直接改钱。 |
| 人物与队伍 | 人物档案、队伍/核心/已知/暂离/归档/死亡状态、关系、位置、目标、关系锚点、高价值记忆 | 人物身份跨分支稳定；分支状态和记忆可随回档恢复。 |
| 预设角色 | 服务端版本化预设、独立预设入口、完整开局初始化、重新开始恢复 | 第一套预设 `Arno` 已接入，包含明确世界说明、3 个地点、4 名队友、24 件物品、5 条事实和 3 条相互关联的剧情线。开场先处理旧友重逢，主线围绕死灵法师复活与王国多队征召展开，不设置固定顺序或强制终点；预设模板不可删除，从模板创建的玩家存档可以独立删除。 |
| 初始人物数据 | 主角与 NPC 的七项属性、专业、能力、背景、关系、装备和资源 | Arno 拥有 2 项能力、4 项专业和 `1,800` 铜币；四名队友各有独立数值、能力与个人物品。 |
| 人物上下文 | 本回合最多 8 名人物，其中默认随行队伍最多 4 名 | 名册总数不受限制；离队与背景人物仍保存在本地。 |
| 人物记忆 | 队伍/核心 30 条，置顶或 recurring 18 条，背景 12 条 | 每名已选人物只把最多 3 条相关记忆送进当前回合。 |
| 世界百科 | 固定百科、一级/二级浏览、全文检索、正文交叉链接与相关推荐 | 搜索同时覆盖标题、正文、分类和检索关键词。 |
| 叙事控制 | 模型选择、密度、节奏、文风、重点、对话、玩家自主性、成熟题材、场景模式、导演注记 | 系统界面中英文可切换；剧情默认中文。 |
| 文本质量防线 | 场景写作规则、原创场景校准库、近期文本重复检测与必要时改写 | 示例用于提取技法，不复制或模仿名作原文。 |
| 隐私 | 个人 SQLite 默认存放在项目外；服务只监听 localhost | 详细边界见 `privacy.md`。 |
| 验证 | Python 回归测试覆盖存档、分支、百科、物品、交易和人物连续性 | 当前测试命令：`npm test`。 |
| 数据保护 | 整库导出、导入、一键本地备份、导入前自动备份与原子恢复 | 导入文件先经过完整性检查与 schema 迁移。 |
| 数据库升级 | 显式 schema 版本、迁移历史与未来版本保护 | 版本同时写入 `user_version` 和迁移记录。 |
| 人物反馈 | 回合后显示新登记人物及关系、位置、状态与记忆变化 | 玩家可直接进入人物面板复核。 |
| 章节摘要 | 从明确回合范围生成带引用的草稿，支持原文核对、编辑、确认与删除 | 摘要保留来源哈希，不进入叙事上下文，也不替代原始回合。 |
| 行动裁定 | 项目 Skill 负责情境判断，本地校验事实、引用、20 点直接对抗与结果边界 | 无骰；普通动作不显示多余机械信息，不合规输出不会进入存档。 |
| 伤势与负荷 | 三级伤势、三条负荷、有来源的状态、逐级恶化与恢复 | 全部进入分支状态，支持检查点、回档和整库备份。 |
| UI 验收 | 桌面、窄屏、语言切换、世界创建、存档分支、人物编辑、百科与重启恢复 | 结果记录于 `docs/UI_TEST_REPORT.md`。 |
| 本地 HTTP 防护 | localhost Host/Origin 校验、写请求标记、媒体类型校验、请求体上限 | JSON 上限 2 MB，数据库导入上限 256 MB。 |
| 生成任务隔离 | 回合开始时固定存档身份，生成期间阻止其他存档写操作 | Codex RPC 默认 60 秒超时，叙事回合默认 4 分钟并在超时后中断。 |
| 自动验证 | 48 项 Python 测试与 57 项 Node 测试 | 共 105 项，覆盖运行依赖、HTTP 边界、存档隔离和核心游戏流程。 |

## 三、当前发布判断

当前版本可以作为 **GitHub 私有开发仓库和团队内部 Agent 模式测试版**
使用。源码、固定设定、测试和维护文档齐全；本地运行版已经完成关键页面、备份、
写请求保护与存档读取验证。

它还不是面向 Steam 普通玩家的独立发行版。当前叙事依赖同一台电脑上已登录的
Codex，离线模式、桌面安装包、首次启动流程、自动更新和更多预设仍需另行开发。
公开发布给玩家之前，还应完成 30–100 回合长线测试，并为非开发者准备安装、
故障恢复和版本升级流程。

## 四、当前仍有意保留为空的内容

这些不是故障，而是等待进一步创作决策的内容。

1. **其余预设角色与开局包**：第一套 `Arno` 已完成；其余六个体验方向仍需逐一
   完成主角、出身、初始伙伴、装备、能力和起始处境设计。
2. **更多开局地点与地区入口**：Arno 已从王冠城旧渡口开始；百科中的其他国家、
   城邦、地域和势力还没有整理成更多可直接选择的入口。
3. **具体主线与角色内容**：固定世界观只提供土壤；任何一局的反派、谜团、
   队友与结局应由该存档生成，而非预先写成全球进行时事件。
4. **更多角色的初始属性**：Arno 与四名初始队友已经拥有差异化七项属性；后续
   预设仍需依据人物事实分别配置，系统不会为旧角色编造统一默认值。
5. **组织与服务实例**：地点与实际路线已经形成持久化闭环，人物、物品和事实也
   能够保存；组织、店铺/服务、地方规则及其关系仍缺少同等级的专用实例记录。
   技术边界见 `docs/DYNAMIC_WORLD_MEMORY.md`。

## 五、已知缺口与建议优先级

### 下一批内容

1. **继续制作预设角色**
   - 沿用 Arno 已验证的数据结构，逐一补齐其余六名角色的世界入口、初始关系、
     属性、能力、装备和可拒绝的开局压力。
   - 每套预设都应先完成内容与回归测试，再进入角色选择界面。

2. **“已招募 / 本次随行”双层切换不再列入计划**
   - 用户认为额外切换会增加管理负担并影响沉浸感。继续沿用当前的简洁人物状态
     与自动上下文选择，不增加战术编队式操作。

### 后续成熟度工作

3. **扩展世界实例记忆**：在已完成的地点与路线闭环上，补齐组织、服务和地方规则，
   再连接相关人物与事件；继续保持有限检索，不做全世界后台模拟。
4. **设定与开局的编辑工作流**：固定百科应保持只读；若将来扩写，使用独立的
   版本化编辑工具和审核流程，而不是游戏内直接改设定。
5. **真实长线游玩验证**：在 30–100 回合的真实战役中记录记忆遗漏、节奏重复、
   摘要质量和检索误差，再据此调整规则。

## 六、推荐推进顺序

1. 已完成 **整库导出/导入与备份、schema 迁移、人物更新反馈**。
2. 已完成 **百科全文检索、交叉链接、相关推荐、可审核章节摘要和 UI 流程验收**。
3. 已完成第一套 `Arno` 开局包；不增加“已招募 / 本次随行”双层管理。
4. 接下来用 Arno 进行几十回合真实游玩，校准地点返回、别名检索和重复生成，再扩展组织与
   服务实例；不做全世界后台模拟。

## 七、交付包内容与使用方式

本次压缩包应包含源代码、固定百科、提示词、文档与测试；不应包含个人
`campaign.sqlite3`、Codex 登录凭据或 `node_modules`。解压后，在 Codex desktop
中打开根目录并运行：

```bash
npm run start
```

如需保留正在游玩的故事，请单独备份：

```text
~/.codex-rpg-memory/campaign.sqlite3
```
