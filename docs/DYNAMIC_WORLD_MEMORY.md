# 世界实例与存档记忆

> 状态：地点实例、上下级归属、实际路线、返回检索、分支恢复与每回合一次的轻量主持人动作已接入运行；组织与服务实例仍待补充
> 用途：规定大纲中的世界如何在玩家经历中逐渐落地，并由存档保持连续、可返回和可检索。

## 一、核心原则

**世界观遵循共同大纲；已经在游戏中成立的具体世界实例跟随存档。**

固定百科定义所有存档共同遵守的世界大纲，例如种族、国家、地理框架、魔法规则、物品类别和历史常识。玩家在一局中真正遇见的人、走进的店、经过的街道、发现的地点、促成的事件与造成的后果，都要在该存档中成为可持续存在的具体记录。

这不是要求每个存档重新生成一套世界。重点是：大纲中尚未具体展开的部分，可以在游玩中被补全；一旦补全，就不能因为玩家离开当前场景而消失，也不能在返回时被另一个随机地点或人物替代。

例如，玩家出生在一间对其人生十分重要的酒吧，或在某条街道上经历关键事件：

- 酒吧与街道立即获得稳定身份，并记录它们属于哪座城区或城市。
- 玩家离开后，它们退出当前上下文，但仍完整保存在存档中。
- 玩家可以通过已知路线再次返回，而不是依赖模型临时“想起”它们。
- 返回时读取原有名称、位置、经营者、关系和最后状态，再根据已经发生的时间与事件更新。
- 若酒吧后来易主、焚毁或停业，应保存为同一地点的状态变化，而不是删除旧地点再生成新地点。

## 二、三层归属

| 层级 | 归属 | 典型内容 | 是否随回档变化 |
| --- | --- | --- | --- |
| 世界基座 | 所有存档共享 | 国家、种族、魔法规则、物品类别、固定历史 | 否 |
| 世界实例 | 单个存档 | 已经在游玩中成立的地点、人物身份、组织、店铺、路线、地方历史 | 身份保留，不能泄漏到其他存档 |
| 分支历史 | 存档中的一条时间线 | 人物所在位置、关系、伤势、营业状态、事件结果、当前局势 | 是 |

“世界实例”不是另一套世界观，而是共同大纲在该局中已经具体化的实体集合。分支则记录这些实体在某条可能历史中的当前状态。

## 三、应当保存什么

动态世界记录以下类型：

- **地点**：聚落、城区、街道、建筑、房间、地标与其包含关系；重要地点必须拥有稳定身份和上级位置。
- **人物**：稳定身份、角色定位、外在特征、目标、关系和重要记忆。
- **组织**：名称、职能、势力范围、成员关系与当前立场。
- **服务与店铺**：所在地点、经营者、服务类型、来源渠道和当前状态。
- **路线**：连接的地点、通常耗时、通行条件与已知风险。
- **事件**：发生了什么、时间、地点、参与者、结果和后续影响。
- **关系**：人物、组织和地点之间已经成立的联系。
- **地方规则**：仅在特定地区成立的法律、习俗、禁忌与现实条件。

系统不把每一句文学描写都变成永久事实。只有会影响以后识别、推理、行动或连续性的内容才进入动态世界。

## 四、事实生命周期

每条记录必须知道自己是什么，而不只是保存一段文本。

| 类型 | 含义 | 处理方式 |
| --- | --- | --- |
| 已确认事实 | 叙事中明确发生或被可靠观察 | 可作为后续裁定依据 |
| 当前状态 | 此刻成立但可能变化 | 写入分支，并保留变更历史 |
| 人物认知 | 某个角色相信或知道的内容 | 只影响该角色，不能冒充客观事实 |
| 未证实传闻 | 有来源但尚未确认 | 可用于剧情，不可直接作为硬边界 |
| 历史事件 | 已经结束但后果仍然存在 | 保留发生时间、参与者与结果 |
| 临时场景细节 | 只服务当前段落的氛围 | 默认不长期保存 |
| 被取代记录 | 曾经成立，后来发生变化 | 留在历史中，不再作为当前状态 |

模型可以提出新增或更新，但本地系统负责验证引用对象、归属存档、分支版本和合法状态变化后再写入。

## 五、按需检索，而非整库输入

“世界不遗忘”指数据库保留结构化记录，不是每回合把整个世界发送给模型。

普通回合只组装一个有上限的相关记忆包：

1. 当前地点及其直接上级地点。
2. 当前在场人物及其少量相关记忆。
3. 与眼前行动直接有关的组织、服务、物品和规则。
4. 正在影响现场的事件与剧情线。
5. 玩家本轮明确提及的旧人物、地点或事件。
6. 少量与上述对象直接相连的固定百科条目。

离开视野的内容继续保存在存档中，但不消耗普通回合的上下文。再次返回时，系统先取回原有实体、位置关系和最后状态，再根据已经发生的时间、事件和因果更新，不能重新生成一个互不相干的替代品。

## 六、世界生长边界

- 共同世界大纲不随存档任意改变；存档只负责持续补全玩家实际接触到的具体部分。
- 世界沿玩家探索、关系和事件传播的范围逐渐变得具体。
- 未接触地区只保留固定百科轮廓，不持续模拟每个居民的生活。
- 远方变化必须来自已经登记的事件、组织计划、时间推进或可信传播。
- 重要 NPC 可以在离场期间推进有限计划；背景人物不进行逐回合模拟。
- 新内容优先复用已存在的地点、人物和关系，只有确实需要时才创建实体。
- 矛盾记录不能被静默覆盖；应当判定为认知差异、状态变化或生成错误。

## 七、分支与回档

分支从创建时继承此前已经成立的存档世界和状态。分支之后发生的状态变化、事件、关系与新发现彼此隔离。

稳定身份也必须遵守时间边界：某人物可以在共同历史中存在，但若他只在分支 A 中首次出现，分支 B 不能因为数据库里已有此人就自动认识他。检索必须同时检查实体的首次成立位置和当前分支可见性。

回档不删除原时间线，而是创建新的分支继续发展。这样每条时间线都能恢复自己的世界状态，同时保持同一存档的共同历史。

## 八、第一阶段实施状态

已经完成：

1. 开局地点自动登记；剧情实际到达的新地点自动成为稳定实体。
2. 地点保存类型、上级地点、描述、氛围、特征、通行条件与最后状态。
3. 玩家离开地点后记录仍存在；地图显示已落地地点和实际走过的路线。
4. 返回已知地点时复用原 ID、原位置关系与原状态，不重新生成替代地点。
5. 实际移动自动登记路线、路线状态和使用次数；仅提到目的地不会制造旅程。
6. 地点和路线状态属于分支，可随检查点、回档和整库备份恢复。
7. 普通回合只读取当前地点、上级地点、相连地点和玩家明确提到的旧地点。
8. 玩家界面只显示世界内信息，不暴露内部 ID 或验证流程。
9. 每轮可以从环境、地点日常、人物计划、已接触剧情压力、时间后果和具体发现中选择至多一次主持人动作，并把原因与结果留给下一轮维持节奏。
