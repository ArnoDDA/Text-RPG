# 持续场景模型与剧情输出框架

正文始终是游戏的主要内容。场景模型不把剧情压缩成面板，也不向玩家列出固定选项；它只保存正文已经建立、下一轮仍可作用的世界事实，使自由输入面对的是同一个连续场景。

每轮输出由三部分组成：

1. 完整剧情正文，描述行动过程、人物反应、环境变化和自然后果；
2. 正文结束后的当前场景快照；
3. 等待玩家通过“行为”和“说话”继续推进的时刻。

后台还会为已完成回合保存一次“主持人动作”。它不显示为玩家选项，也不增加独立面板；它只记录本轮除主角行动结果之外，世界是否发生了一项有根据的变化。

快照最多保存八名当前重要参与者、八个可以实际作用的环境要素和四项正在推进的压力，同时记录玩家的相对位置。它们只能来自玩家当前能够观察或使用的内容，不能把装饰物、秘密和可能出现的未来事件塞进场景。

参与者记录位置、正在做的事、可见状态和当前立场；环境要素可以是路线、地形、物体、危险、掩护、线索或服务；压力表示已经开始推进、即使玩家不处理也会继续发展的事情。它们都使用稳定标识，移动、受伤、离场、堵塞或解除必须先在正文中发生，再更新快照。

界面可以把参与者和环境要素作为“文本抓手”显示。点击只会把名称带入行为输入框，帮助准确指代，不会替玩家生成行为，也不会限制玩家采用未被列举的方法。

场景状态描述世界此刻正在发生什么，不是文风标签，也不是另一套行动裁定。它只保存两个彼此独立的维度：

| 维度 | 状态 | 含义 |
| --- | --- | --- |
| 当前活动 | 日常、交谈、探索、行旅、交易、休整 | 人物此刻主要在做什么 |
| 威胁阶段 | 平稳、紧张、迫近、战斗、战后 | 眼前危险发展到了哪一步 |

因此，人物可以在迫近的危险中交谈，也可以在平稳环境中探索。地点氛围只提供倾向：身处黑龙山谷不自动进入战斗，酒馆中发生袭击则可以进入战斗。

## 战斗边界

只有一方已经实施即时敌对行动，并且仍有能够形成实际对抗的对象时，场景才进入“战斗”。争吵、威胁、拔出武器、察觉跟踪或怀疑伏击分别属于紧张或迫近，不自动算战斗。

战斗一旦开始，会跨回合持续。玩家防御、观察、说话、寻找掩体或尝试逃跑时，不能因为本轮没有攻击动作就退出战斗。只有逃脱、投降、失去战斗能力、双方分离或明确停止敌对后才结束；通常先进入“战后”，再回到平稳。保存、读档与时间线分支均恢复对应回合的场景状态。

## 输出影响

- 当前威胁为战斗时，下一轮优先使用紧凑的行动场景节奏，但仍遵守玩家只授权一个行动步骤的规则。
- 状态只影响叙事关注点、NPC即时反应和上下文，不自行决定胜负。
- 每轮结束只记录状态以及一条可观察的事实依据，不向玩家显示后台判断过程。
- 旧存档没有状态字段时按“日常／平稳”读取，不改写原有剧情。

## 主持人动作

主持人动作每轮最多一项，也可以为空。它从已经存在的原因中选择：环境反应、地点日常、人物计划、当前剧情压力、实际经过的时间，或通过具体痕迹显露的发现。它不能凭空制造反转，也不要求每轮出现危险。

观察、等待、失败、旅行、休息和转场通常给世界留下更多行动空间；很小的整理动作、已经由主角造成充分变化的回合、安静的人物片刻则可以不追加变化。远处事件只有在时间确实推进，或现场出现可信的消息与痕迹时才能进入正文。

非空动作必须先自然出现在正文中，再更新对应记录：空间变化进入场景快照，人物计划变化进入人物状态，剧情压力推进进入剧情线，地点的长期变化进入原地点记录，重要事实进入事件或事实账本。普通地点日常若不影响未来判断，不需要被提升为永久世界事实。
