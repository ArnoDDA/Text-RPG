# Secret Fire v0.3.0 UI 验收报告

验收日期：2026-09-16
环境：macOS、Google Chrome、Node.js 25、Python 3、隔离的临时 SQLite 存档
结果：**通过**

## 验收方式

本次使用本机真实 Chrome 页面连接本机 Secret Fire 服务，并通过浏览器调试协议
执行点击、输入、表单提交、视口切换和页面状态核对；同时人工检查了桌面截图。
任务环境未开放交互式浏览器控制界面，因此不能进行鼠标驱动的逐项人工点击，这一
限制不影响页面脚本、布局、网络请求和持久化路径的实际执行。

测试全部使用临时数据库，不读取或改写个人正式存档。章节草稿使用当前电脑已登录的
Codex 生成，其余数据均为验收样例。

## 验收中发现并修复的问题

首次测试发现：创建世界时若标题完全由中文组成，标题曾被直接当作内部存档 ID，
会触发 ASCII ID 校验并导致创建失败。现已将“玩家可见标题”与“内部稳定 ID”分离：
标题完整保留，内部 ID 使用随机生成的安全 ASCII 值。修复后以“灰岸来信”重新走完
创建流程，世界、主角“林遥”、地点“王冠城 · 旧渡口”和初始物品“母亲的铜钥匙”
均正确保存与回显。

## 章节摘要核验记录

- 来源范围：回合 1–3。
- 草稿标题：`黑鸦酒馆外的王室戒指`。
- 人工修改标题：`第一章：戒指与黑鸦酒馆`。
- 摘要逐段含 `[回合 1]`、`[回合 2–3]` 等来源引用。
- 保存后来源哈希继续匹配，确认按钮可用。
- 服务重启后状态仍为 `approved`，原始回合数量与正文不变。

## 结论

v0.3.0 的百科搜索、正文交叉链接、相关推荐和可审核章节摘要已形成可用的完整界面
闭环。自动化回归测试仍负责底层分支、迁移、备份恢复和摘要隔离；下一阶段应转入
30–100 回合的真实长线游玩，观察检索误差、摘要质量与叙事重复，而不是继续增加
管理型开关。
