# Secret Fire 玩法底层系统总纲

> 状态：持续实施；统一行动裁定、伤势/负荷与交易闭环第一版已接入
> 用途：统一记录玩法基座、系统边界与后续设计顺序。本文是内部设计文档，不是玩家百科正文。

## 一、总体方向

Secret Fire 的核心不是把战斗、交涉、潜行和探索做成彼此割裂的小游戏，而是让它们共同使用一套世界规则。

- 玩家用自然语言自由描述行动，不从固定指令菜单中选择。
- 不使用骰子；结果由既有事实、七项属性、专业能力、当前状态、环境、方法与代价共同决定。
- 属性负责提供能力边界，但不能单独决定所有成败。
- 只有结果存在真实分歧且失败具有意义时才进行裁定；吃饭、开门、正常行走等确定行为不计算。
- AI 可以理解开放行动、扮演人物并提出结果，但不能越过已经固定的能力鸿沟、身份、资源和世界事实。
- 所有重要变化都应落入可保存的结构化状态，不能只存在于一段叙述中。
- 固定百科提供所有存档共用的世界大纲；游玩中已经成立的具体人物、地点、组织、事件与地方历史由该存档持续保存，离开当前场景也不会消失。
- “世界不遗忘”由本地数据库负责；模型每回合只读取当前相关的有限记忆包。

## 二、目前已经确定的系统

### 1. 七项属性

使用体魄、身手、感知、智识、心性、魅力、灵能七项属性，统一采用 `1–100+` 数值。

- 相差 `10` 点形成明显能力门槛。
- 相差 `20` 点后，以同一种能力正面对抗通常无法逾越。
- 不计算属性总和，也不生成“综合战力”。
- 专业、装备、伤势、身份、关系和特殊能力均独立于属性记录。

详细定义见 [七项属性与世界裁定规则](ATTRIBUTE_SYSTEM.md)。

### 2. 能力、法术与技法体系

魔法不再设计成孤立系统。法术、神术、武技、专业技巧、血脉特性、物品赋能和大型仪式共用一套能力模型，分别通过来源、权限、代价、使用条件和反制方式体现差异。

第一版保留容易理解的能力概念，例如已掌握能力、维持、打断、反制、仪式和休息恢复，但不采用骰子、豁免检定或僵硬的法术位。魔法术式使用原创的一至八环分类来说明复杂度、准备与通常影响范围；环阶不等于角色等级、每日次数或固定伤害。能力规模仍沿用 `1–100+` 世界标尺；消耗使用明确代价与少量负荷状态，不把所有能力压缩成同一个法力条。

角色可在已经掌握的能力边界内改变目标、规模、表现和组合方式，但不能因描述巧妙而获得不存在的效果、知识或权限。详细方案见 [能力、法术与技法底层系统](ABILITY_SYSTEM.md)。

### 3. 简单交易系统

交易只承担“当前能否交换、资源是否足够、交换会改变什么”，不做复杂商业模拟，也不给每件物品设置脱离情境的永久价格。

- 钱包以铜币为最小整数单位，本地界面按 `1 金 = 10 银 = 100 铜` 换算显示；地区币名、票据和信用凭证仍可留在故事层。
- AI 只能根据当前场景提出购买、出售、报酬或支付报价，不能直接改变钱包或物品归属。
- 地区供给、具体来源、物品状态、关系与议价过程共同形成当次报价；价格不是物品卡的固有属性。
- 当前报价只在对应剧情场景有效，进入下一剧情回合后失效。
- 玩家确认后，本地 SQLite 在同一事务内更新余额、物品数量或归属，并追加交易记录；任一校验失败都不会留下半笔交易。
- 不为每名商人长期模拟完整库存，也不让模型每回合扫描或估价整个背包。
- 债务、赃物、违禁品、人情与信用仍属于后续关系和法律系统，不压缩成单一价格数值。

## 三、还需要建立的核心系统

| 系统 | 解决的问题 | 建议方向 |
| --- | --- | --- |
| 统一行动裁定 | 玩家可以说任何行动，系统如何给出稳定结果 | 第一版已运行：项目 Skill 判断情境，本地验证事实、20 点直接对抗与合法结果。 |
| 场景状态 | 当前是日常、探索、行旅还是战斗，下一轮如何保持连续 | 分开记录当前活动与威胁阶段；战斗跨回合持续，直到世界内真正结束。详见 [场景状态与剧情输出框架](SCENE_STATE.md)。 |
| 专业与能力 | 智识高不等于会医术，身手高不等于会剑术 | 用明确的专业、招式、知识和能力标签记录“学会了什么”；数量可增长，但不再增加基础属性。 |
| 状态与资源 | 受伤、疲劳、中毒、恐惧、法力不足如何持续影响行动 | 第一版已运行：三级伤势、三类四阶段负荷、有来源的持续状态，以及本地钱包和交易流水。 |
| 物品与装备 | 玩家拥有什么、能否使用、是否真的带在身上 | 延续现有物品账本，补充使用条件、装备效果、消耗、损坏与特殊性质。 |
| 知识与秘密 | 玩家、角色与 NPC 知道的内容不同 | 区分客观事实、角色已知、NPC 已知、误解与秘密；未获得的信息不能直接用于行动。 |
| 关系、声望与身份 | 为什么同一句话面对不同人物会有不同结果 | 分别记录私人关系、群体声望、正式身份、债务、誓言与通缉，不压缩成单一“好感度”。 |
| NPC 动机与选择 | 每个人如何拥有自己的想法并推动剧情 | 为重要人物保存目标、恐惧、底线、资源、关系和当前计划；只在相关时推进，不持续模拟全世界。 |
| 目标、线索与承诺 | 玩家正在追查什么，哪些委托、约定和机会仍然有效 | 不依赖僵硬的任务清单；分别记录目标、已知线索、相关人物、期限与当前结果，让玩家可以放弃、绕行或用意外方式解决。 |
| 时间与世界状态 | 旅行、休息、期限和远方事件如何真实发生 | 使用明确时间推进、地点距离、事件期限和有限的后台事件；世界变化必须有原因和传播路径。 |
| 世界实例记忆 | 已经见过的人与地点如何在几十回合后仍可识别、可返回 | 地点、上级归属、实际路线、状态与按需检索第一版已运行；组织与服务实例仍待补充。详见 [世界实例与存档记忆](DYNAMIC_WORLD_MEMORY.md)。 |
| 成长与学习 | 玩家如何变强，又不变成单纯刷等级 | 属性成长缓慢且需要长期依据；专业、知识、关系、装备与新能力构成主要成长。 |
| 失败、伤害与死亡 | 成败如何产生重量，又不轻易终止故事 | 失败优先产生代价、伤势、暴露、失去机会或局势恶化；死亡只在风险明确且事实足够时发生。 |

## 四、不应拆成独立底层的内容

以下内容很重要，但更适合作为统一系统的应用场景，而不是各自建立一套互不相容的规则：

- **战斗**：统一行动裁定 + 属性 + 专业 + 装备 + 状态 + 环境。
- **交涉**：统一行动裁定 + 动机 + 关系 + 身份 + 信息 + 行动方式。
- **潜行与盗窃**：统一行动裁定 + 感知/身手 + 专业 + 警戒 + 地形 + 时间。
- **探索与调查**：知识与秘密 + 感知 + 专业 + 地点状态 + 信息传播。
- **旅行与生存**：时间 + 地图距离 + 补给 + 环境 + 状态。
- **制作与炼金**：专业 + 配方知识 + 材料 + 工具 + 时间；可在核心稳定后再补。

这样可以避免系统越来越多，却在同一场景中得出互相冲突的结论。

## 五、建议的设计顺序

1. **统一行动裁定**：先确定所有玩法共同使用的成败语言和边界。
2. **专业、状态与资源**：补足七项属性无法表达的训练、伤势和消耗。
3. **能力、法术与技法体系**：在统一裁定之上接入专业、技法、特性、仪式、负荷与反制规则。
4. **物品、装备与简单交易**：让获取、使用和交换资源形成闭环。
5. **世界实例、知识、关系、目标与 NPC 动机**：先让已经出现的地点和人物可以保存、返回和积累，再支撑秘密、委托、背叛与人物自主选择。
6. **时间、世界变化与成长**：在已经落地的世界实例上推进有限的因果变化，支撑长线剧情。
7. **制作、生存、法律等扩展模块**：只在实际游玩证明有需要时加入。

## 六、当前需要继续决定的问题

- 三类负荷在真实游玩中是否足够轻量，是否还需要继续合并？
- 三级伤势在长线游玩中的恶化与恢复速度是否合适？
- 专业能力采用数值等级，还是“入门、熟练、大师”等少量阶段？
- 成长是否允许直接提高七项属性，以及提高一次需要怎样的剧情依据？
- NPC 的自主计划推进到什么粒度，才能既有生命感又不造成过高计算压力？

这些问题需要通过真实游玩校准。统一行动裁定、伤势/负荷和简单交易已经有可运行第一版；角色创建中的属性固化继续暂缓，下一步先通过实际回合检验这些系统。

第一版玩法方案见 [统一行动裁定](ACTION_RESOLUTION.md)，运行与数据设计见
[统一行动裁定技术设计](ACTION_RESOLUTION_TECHNICAL_DESIGN.md)。
