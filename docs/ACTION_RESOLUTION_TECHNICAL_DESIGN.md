# Secret Fire 统一行动裁定：运行设计

> 状态：第一版已接入运行时
> 依赖：[玩法规则](ACTION_RESOLUTION.md)、[七项属性](ATTRIBUTE_SYSTEM.md)、项目 Skill `.agents/skills/secret-fire-adjudicator/`
> 目标：在自由输入下得到稳定、可复核、可回档的无骰结果，同时保留真实情境中的例外。

## 一、运行链路

```text
玩家输入
→ 项目 Skill 理解目标、方法和第一个边界
→ Skill 提出结构化裁定与后果
→ 本地校验事实、20 点鸿沟和状态转移
→ 模型输出相符的剧情
→ SQLite 保存回合、裁定与后果
```

模型第一次返回不合法结构、引用不存在的能力或越过硬边界时，服务端允许一次纠正。再次不合规则整轮不保存。

项目 Skill 是游戏系统的一部分，随源代码放在 `.agents/skills/secret-fire-adjudicator/`。服务端每个剧情回合都显式调用 `$secret-fire-adjudicator`，不依赖模型自行判断是否加载。

## 二、职责边界

### Skill 负责

- 区分目标、方法、期望结果与本回合停止位置；
- 判断行动是自动、争议还是当前方法不可能；
- 为争议行动选择一项主要属性；
- 判断是否属于同一种能力的直接对抗；
- 结合专业、能力、装备、伤势、环境、关系与 NPC 动机选择可信结果；
- 提出伤势、负荷、状态及恢复；
- 让结构化结果与玩家看到的叙述一致。

### 本地系统负责

- 属性、能力、专业、物品、人物与场景引用是否真实存在；
- AI 不得临时获得能力、知识、装备或数值；
- 直接对抗中已固定属性的 20 点鸿沟；
- 伤势和负荷只能按合法阶段变化；
- 普通失败不得突然造成重伤、危重、死亡或永久残疾；
- 所有后果进入当前时间线，并随检查点与分支恢复。

本地系统不机械决定每个接近结果。它计算允许范围或否决不可能结果，具体情境判断仍由 Skill 完成。

## 三、行动结构

每个可保存回合必须包含：

- `action_frame`：目标、方法、期望结果、解释、第一边界和玩家原话；
- `resolution`：模式、主要属性、是否直接对抗、对手、依据、结果、高风险标记与后果；
- `narration`：与裁定一致的中文剧情；
- `manifest`：场景、人物、事实、认知与剧情线变化。

结果分为：`impossible`、`blocked`、`limited_success`、`success`、`strong_success`。

普通无争议行动使用 `automatic + success`，不选择属性，也不在界面中额外展示机械裁定。只有争议、不可能或产生持续后果的回合显示折叠的“裁定依据”。

## 四、20 点鸿沟

20 点规则只在以下条件同时满足时启用：

1. 双方以对应能力正面对抗；
2. 对抗目标没有改变；
3. 没有决定性事实把问题改成另一种行动；
4. 双方相关属性已经在本地固定。

因此普通矮人不能赤手空拳击败古龙，但可以利用出口、地形、计谋、对方动机或注意力逃离。逃离不是把低体魄硬算赢高体魄，而是重新建立了另一项行动。

若属性尚未固定，本地返回 `unfixed`，绝不让模型临时编造数值。待角色创建或人物固化流程补齐属性后，同一校验器会自动启用数值鸿沟。

## 五、伤势、负荷与状态

### 伤势

内部阶段为 `minor → serious → critical`。新增普通伤势只能从轻伤开始；每回合最多改变一级。危重和永久伤害必须有上一回合已经明确的高风险环境，永久伤害还必须处于危重阶段。

每项伤势记录稳定 ID、名称、受影响功能、来源、开始回合、恢复条件与是否永久。

### 负荷

- 身体：`稳定 → 疲劳 → 透支 → 崩溃`
- 专注：`稳定 → 分散 → 动摇 → 失控`
- 灵能：`稳定 → 吃力 → 过载 → 枯竭`

每回合每条记录只移动一级。推进必须来自明确的剧烈消耗、重复使用、过度施展或能力代价；恢复必须在叙述中出现休息、治疗、时间、能力或恢复条件。

### 状态

中毒、束缚、失明、恐慌或持续魔法效果使用独立状态，记录实际影响、来源和解除条件。状态不与伤势、负荷重复表达同一件事。

## 六、存储与界面

- 裁定保存在 `turns.scene_json.resolution`；
- 伤势、负荷和状态保存在玩家的分支状态 `entity_states.state_json.mechanics`；
- 普通叙事 `state_updates` 无权修改属性、能力、专业、伤势、负荷或状态；
- 角色卡始终显示三类负荷，有伤势或状态时显示其实际影响与恢复条件；
- 检查点、分支、恢复和整库备份沿用现有状态账本，无需新增独立存档表。

## 七、当前限制

新建角色尚未分配七项固定属性。当前版本可以运行情境裁定、能力/物品引用校验和后果系统，但只有存档中已有明确属性时，本地才会执行数值型 20 点比较。下一阶段应在角色创建中设计差异化属性生成或分配方式，而不是为所有旧角色套用相同默认值。
